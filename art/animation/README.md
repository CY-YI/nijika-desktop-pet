## 给视频生成工具的提示词

使用者上传上述原始 PNG 作为角色参考，再粘贴通用约束和某一段动作；不要上传客户端配置、消息库或任何密钥。

通用约束：

```text
以我提供的角色原图作为唯一角色参考，生成固定机位、2D日式手绘Q版桌宠动作片段。保持原图的脸型、头身比例、金色单马尾、校服颜色、蝴蝶结、完整双腿和鞋子，保留正面坐姿，不变成3D，不重新设计人物。线条和涂色保持一致，不加景物、字幕、镜头运动、变焦或景深。画面中只出现这一个角色。
角色在整段视频中的位置和大小固定，头发、手脚始终完整在画幅内，四周留足余量，避免随动作自动裁切。角色不要被压扁拉长，不要突然变脸、变装或多出肢体。
背景始终为无纹理、无阴影、无渐变的纯蓝色 #0000FF，供后续透明抠像；纯蓝色不能出现在角色、服饰、道具或特效中。不要用绿幕，角色的绿色外套必须保留。无音频。输出连续视频，不要用几张静态图淡入淡出代替动作。
首尾各约0.6秒回到与参考相近的标准坐姿，表情自然，末尾平稳收势，便于后续剪辑和衔接。
```

AN01 附加：

```text
时长6秒。0–0.6秒保持参考坐姿；0.6–2秒轻呼吸，胸肩只有微小起伏；2–3秒自然眨眼一次，闭合和睁开连续；3–5秒微微抬眼看向用户，马尾有轻微滞后摆动；5–6秒平稳恢复原姿态。双腿和鞋子位置稳定。不要全身机械摇摆，不重复快速抖动。
```

AN02 附加：

```text
时长6秒。0–0.6秒保持参考坐姿；0.6–2秒自然抬起角色的一只手，肩膀、手肘与手腕有连贯的运动；2–4秒微笑并温柔挥手两次，另一只手和双腿保持自然；4–5.4秒收回手，头发轻轻跟随并停稳；5.4–6秒恢复参考坐姿。手臂不能穿过脸或头发，手指和衣袖保持一致，不增加多余手臂。
```

AN03 附加：

```text
时长6秒。0–0.6秒保持参考坐姿；0.6–2秒头部轻微向一侧倾斜，眼睛稍向上看，呈现思考神态；2–3.5秒停留并轻眨眼；3.5–5.4秒抬眼看向用户，露出一点理解后的微笑，头部回正，马尾略滞后摆动再停稳；5.4–6秒恢复参考坐姿。脸部宽度和五官位置保持自然，不通过整张图旋转来完成歪头。
```

提示词是约束目标，不保证生成器遵守；视频中出现平台水印、人物变形、背景污染或严重遮挡时先处理来源与重生成问题，不默认移除第三方标识。

## 可复用的本地素材转换工具

仅维护者需要 Python 3.12 和 `tools/requirements-animation.txt`；`imageio-ffmpeg==0.6.0` 提供本地 FFmpeg，本轮实际版本为 7.1。它不加入桌宠运行依赖或安装包。技术依据：[FFmpeg 滤镜文档](https://ffmpeg.org/ffmpeg-all.html)、[imageio-ffmpeg](https://github.com/imageio/imageio-ffmpeg)。

```powershell
.\.venv\Scripts\python.exe -m pip install -r tools\requirements-animation.txt
.\.venv\Scripts\python.exe tools\prepare_animation.py <源片绝对路径> <新输出.webp绝对路径>
# 本轮源片实测蓝底偏离纯蓝，抽样后显式指定；不对未知素材盲用这些参数。
.\.venv\Scripts\python.exe tools\prepare_animation.py diagnostics\animation-samples\AN01-idle-source.mp4 diagnostics\animation-samples\AN01-idle-review-v2.webp --key-color '#3E90CD' --lossy
# 复用已实现的指定区域清色和往返循环；坐标只能在看过该原片后使用。
# 输出须采用尚不存在的新名字，下面的 v5 是复现示例，不是已生成文件。
.\.venv\Scripts\python.exe tools\prepare_animation.py diagnostics\animation-samples\AN01-idle-source.mp4 diagnostics\animation-samples\AN01-idle-review-v5.webp --width 320 --quality 80 --key-color '#3E90CD' --lossy --clean-blue-shadows --shadow-region 0.28 0.70 0.66 0.96 --loop-mode ping-pong --max-seconds 10.08
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_animation_preparation.py -v
```

工具只处理本地短片，默认保留源帧率并以 24 fps 为上限，不增帧；蓝色键控、边缘去色、缩放、去音轨并编码透明 WebP。默认无损，`--lossy --quality 85` 可生成较小审阅副本。`--clean-blue-shadows` 必须同时给 `--shadow-region X0 Y0 X1 Y1`（0–1 归一化矩形），只在人工核实区域处理深蓝残色，不能全屏清掉半透明平台标识。`--loop-mode ping-pong` 缓冲并反向播放短片，附 `ping_pong_endpoints=single` 报告，不能宣称重建了自然闭环运动。

只允许蓝色系键色，避免误用绿幕损坏校服。不存在透明像素或只有静帧时拒绝输出；已有输出或报告均不覆盖，不写真实通知库、不导入皮肤。逐像素检查与人工视觉审阅仍必需；工具没有自动分割、修手、修脸、自然无缝循环或去标识能力。五项实际合成视频回归覆盖保绿/白色及区域外半透明叠字、蓝底/区域深蓝移除、低帧率、源/旧文件保留、参数限额，以及往返端点单次访问与固定帧间隔。

## 接收与验收约定

### 2026-10-26：原生视频对照审阅

`tools/review_animation.py` 从已存在的 V4 导出 VP9-alpha 视频，并从原片生成同尺寸、同帧顺序的蓝底对照。不是重新生成动作或修脸；原片、原图、V4 与平台标识保持原样，不覆盖旧目录。Python 按单帧 RGBA 提交编码，不存 480 张帧列表；编码器/解码器和浏览器另有缓冲，尚未测得正式桌面内存预算。

实际结果在忽略目录 `diagnostics/animation-review-20261026/idle-pair-v3/`：透明视频 4,643,699 字节（约 4.64 MB），两份各 480 帧、320×427、24 fps、20 秒；另有两张从已编码视频解码出的首帧 PNG，供浏览器完成视频合成前显示角色。源 WebP 的整数毫秒时序与 24 fps 相差合计 1 ms，没有增帧或去掉动作停势。导出拒绝含额外停顿的可变时序，不擅自改成恒定帧率。

```powershell
# 在项目根目录执行；仅维护者需要已有的可选动画依赖。
# 新复现请改用不存在的目录，工具不会覆盖已生成结果。
.\.venv\Scripts\python.exe tools\review_animation.py export diagnostics\animation-samples\AN01-idle-source.mp4 diagnostics\animation-samples\AN01-idle-review-20261025-v4.webp diagnostics\animation-review-local
.\.venv\Scripts\python.exe tools\review_animation.py serve diagnostics\animation-review-20261026\idle-pair-v3
# 打开 serve 实际输出的 http://127.0.0.1:<空闲端口>，Ctrl+C 停止维护服务。
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_animation_review.py -v
```

维护页提供一起播放/暂停、从头重播、逐帧、0.5× 慢放、浅色/深色/棋盘格和往返/循环跳转；离开页面暂停，不自动播放。两段 `<video>` 使用同源首帧 `poster`，首帧解码尚未完成时也能看到角色；原生 video 解码避免 JavaScript 预加载全部 RGBA 帧。它是独立维护页，没有并入设置中心、桌面或皮肤协议。服务只读、仅回环、固定文件映射，支持媒体 Range，拒绝跨站/任意路径和写入；不接触 Agent 配置/队列。

四项真实视频/HTTP 回归覆盖透明与保绿/白标识、往返帧序/容器时长、旧文件/来源摘要保护、不吞额外停势、媒体跳转与跨站/路径拒绝。初版 `idle-pair-v1/` 发现源对照容器少报一帧时长（19.958 对 20 秒），保留为时序修复证据；V2 显式恒定输出后均为 20 秒。内置浏览器已检查实际连续循环、控制、透明背景、逐帧同步和窄屏；截图与后续检查点在其上级目录。编码技术检查通过仍不能替代脸型、姿态与反向感的美术认可。

源文件建议 `AN01-idle.mp4`、`AN02-wave.mp4`、`AN03-think.mp4`。一段一个动作；保留原始帧率和分辨率，不先转成 GIF。MP4 本身通常没有 alpha，蓝色背景不等于透明。

取得源片后才执行抠像、边缘去色、位置归一化、首尾衔接与连续播放检查。正式输出可评估透明 WebP（便于现有 Pillow 解码）或 VP9-alpha WebM（需验证解码/宿主），此刻尚未选定或改造桌面播放器。不通过重复帧冒称提高了真实帧率。

逐项审阅：角色是否一致；绿色外套是否完整；头发/手指边缘是否有蓝边和孔洞；完整腿部是否被裁切；动作是否连贯且有自然停势；循环/跨动作是否跳位；持续播放是否拖慢既有通知。只有小样视觉通过后，才开发桌面动作消费和优先级，不替换正式 EXE 试错。

# BEGIN NIJIKA-DSH-DIALOG
For DSH work that needs a concrete user choice or review of a completed result, load the nijika-dsh-dialog skill and use the mcp__nijika_pet tools. Multi-step setup guidance, changed files, tests, and diagnostic conclusions count as reviewable results even when delivered as prose. Do not notify for a brief factual reply. Resolve short decisions and reviews in the desktop bubble; for longer results send one completion notice before the final chat response. Pending only means queued, never approved or confirmed visible. For a decision, repeat 45-second wait_for_reply calls on the same request ID when one wait returns pending, as the skill specifies; do not end the turn after one timeout. On any later turn with an unresolved Nijika request ID, read get_reply first, especially when the user says “继续” or “我回复了”. After an answered click, state the chosen option in this same DSH conversation before continuing. If the tools are unavailable, continue in chat without blocking the task.

虹夏桌宠｜安装后使用与 Agent 配置
适用：Windows 10/11，64 位。

一、启动与设置
1. 双击桌面的“虹夏桌宠”即可显示角色。
2. 双击“虹夏桌宠设置”打开设置中心；也可右键角色选择设置。
3. 在“角色衣橱”导入 PNG 或多帧 ZIP；在“互动与养成”调整动作。
4. 安装时勾选“登录 Windows 时启动虹夏桌宠”即可开机自启。
5. 安装位置默认为 %LOCALAPPDATA%\NijikaDesktopPet\app。
   桌宠本体不需要 Python，也不需要管理员权限。

二、接入你的 AI 客户端
1. 双击“虹夏桌宠设置”→“Agent 接入”→“扫描本机”。
2. 勾选 Codex、ChatGPT Work、DSH、Claude Code、Gemini CLI 或 Copilot CLI。
3. 点“预览勾选项”→检查文件路径、来源和管理归属→“应用可接入项”。
   每项分别显示结果；冲突项不写入，其他成功项保留。原文件更新前会备份。
   MAGPIE 管理项只登记档案，不重复写入；仍由 MAGPIE 同步到目标客户端。
4. 在下方伙伴卡片打开“接入步骤”，按提示重载并做真实测试。
   需要 AI 协助时复制提示词；里面已带本机路径、配置和规则，无需填密钥。
5. 按客户端要求重载连接或打开新任务；有本人授权/信任提示时亲自处理。
   配好后保持桌宠运行，不必每轮聊天重复配置。

注意：Work 仅限本机任务，现有插件需要 Codex CLI 和 python.exe。
扫描会分别列出 VS Code 中已安装的 Codex、Claude Code、DSH、CodeBuddy 和 GitHub Copilot Chat。
这些具体扩展用“生成接入指引”；气泡目标格式为“VS Code · 扩展/Agent”。
Obsidian、WorkBuddy 等同类入口也按相同方式生成指引。
复制提示词给能操作本机的 AI，由它核对具体扩展或工作区后接入。
也可用右上角“添加 Agent”单独指定配置目录。不要把固定来源共用到所有软件。
普通网页聊天不能配置本机 MCP。不要双击“虹夏MCP-v2.exe”，它由 AI 客户端启动。

三、做一次真实测试
在接入后的 AI 新任务里，复制发送：

请用虹夏的 request_decision 问我“先检查哪项？”。选项“界面”，说明“优先检查界面按钮”，标为推荐；选项“提醒”，说明“优先检查桌面提醒”。等待我在桌面点击，在本会话复述选择，再用 show_completion 发一条完成提醒。

验收：桌面出现选择气泡→点击后 AI 读回你的选择→随后收到完成提醒。
设置页的“发送测试提醒”只验证本机显示，不能代替上面的 AI 实测。
在 VS Code 扩展中测试时，可在同一个新任务里补充：

调用虹夏 show_completion 时，请设置 task="VS Code 来源验证"，
summary="扩展真实连接测试"，agent_name="Codex"（或当前扩展名），software="VS Code"。

预期头部为“VS Code · Codex”等具体名称；若仍显示旧顺序，重载该扩展的虹夏 MCP 后新建任务。

四、升级、卸载与问题排查
升级：运行新版 Setup EXE 即可；无需先卸载旧版。
卸载：打开 Windows“设置→应用→已安装的应用”，选择“虹夏桌宠”→“卸载”。
升级和卸载不会删除 %USERPROFILE%\.nijika-desktop-pet 中的消息、皮肤和 Agent 档案，
也不会自动删除各 AI 客户端里的 MCP、技能或权限配置。

没有气泡怎么办：
先确认角色已启动，再到 Agent 卡片的“接入步骤”核对配置并测试提醒。
本机测试正常、AI 没反应：重载该客户端 MCP，在新任务重试第三部分。
任务已结束后才点击选择：回原 AI 会话说“继续”，让它读取此前回执。
命令授权气泡只是提醒，仍须在 AI 客户端原审批窗口批准。
Work/DSH 当前没有原生审批自动提醒桥接；MCP 注册不等于所有事件自动提醒。
VS Code 扩展扫描只能确认扩展文件已安装，不能证明扩展已启用或已经调用成功。
